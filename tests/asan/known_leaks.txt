# Files with KNOWN remaining leaks, allowlisted so `run.sh --gate-leaks` fails only on
# NEW ones.
#
# CALIBRATED TO M6 (5/5, teardown at refcount zero) -- the end of the drop stack. Entries
# must still be DELETED as whatever owns them is fixed, not carried forward: a line that
# stops leaking and stays here silently re-admits the leak later.
#
# Measured totals: 11 files, 59760 bytes (58656 of it one coroutine stack, below).
# M5 cleared 11 of the 22 files listed at M3, all of the closure-capture class:
# constrained_impl, method_calls, handle_multiple_effects, closure_capture_across_performs,
# handler_owned_state, and stdlib-tests/{char,early_return,fail,math,string,throw}.
# M6 cleared none of these 11 -- its subject is shared pointees that own payloads, and all
# nine of its own tests are leak-free. What is left below is other classes.
#
# --- the abort contract (owned by the abort design, not a later pick) ---
#
#   A handler that completes without resuming discards the suspended continuation.
#   Nothing on it is torn down: no drops run, and nothing double-frees.
#
#   effects/drop_matrix/abort_pinned_leak.an -- 68 bytes, the two continuation Strings,
#     in 4 allocations. The coroutine buffer itself is freed (mco_coro_free runs).
#
#   effects/abort_within_coroutine.an -- 58656 bytes: a WHOLE coroutine stack from
#     mco_create. The cross-stack case: the abort longjmps from the inner generator's
#     coroutine to a setjmp on the OUTER generator's coroutine, so the inner one is never
#     mco_destroy'd. Isolated at M3 -- the same nesting without the abort leaks nothing,
#     and the same nesting through Std.Stream.foldr is clean, so this is the discarded
#     continuation, not the stream shape. Freeing it needs the abort path to destroy the
#     coroutines it unwinds past. (M5 cleared this file's other 32 bytes of payload.)
#
# --- Drop impl not in scope at the use site ---
#
#   A container's `Drop` impl lives in its own module: `import Std.Vec` does NOT bring it
#   in, only `import Std.Vec.drop_vec` does. Drop synthesis never sees it, derives a
#   structural drop over all-Copy fields, prunes to None, and the buffer leaks. The open
#   question is whether the fix is the import or module-level impl visibility, so the
#   test files are left alone pending that decision.
#
#   stdlib-tests/env.an (24), stdlib-tests/io.an (108), stdlib-tests/vec.an (464),
#   implicit_import.an (8).
#
# --- Drop impl IS imported and it still leaks ---
#
#   stdlib-tests/map.an (84, drop_hashmap), stdlib-tests/rc.an (32, drop_rc),
#   stdlib-tests/seq.an (148, drop_seq). Plain `main` locals; rc.an also does manual
#   inc_ref_count/dec_ref_count bookkeeping. Unowned, needs a fresh look.
#
# --- a generic Vec local with no witness to drop it ---
#
#   stdlib-tests/stream.an -- 704 bytes at M3, 160 now: M5 took the closure-capture bulk,
#   and M6 did not touch the rest (guessing it would was wrong -- it is not a shared
#   payload). Traced to `Stream.map2`, whose `v1 = Vec.of s1` / `v2 = Vec.of s2` locals are
#   never dropped, at its two call sites in the test (map2 and zip, which delegates to it):
#   4 buffers, 64 + 32 + 32 + 32. Dropping a `Vec a` needs a `Drop a` witness, and neither
#   `map2` nor `zip` declares one -- they carry only `{Copy a} {Copy b}`. Adding `{Drop a}
#   {Drop b}` to both does clear it, but that changes a stdlib signature and belongs to the
#   same open decision as the class above, not here.
#
#   Not from the effects rebase: `map2`'s body, its constraints and the Prelude's whole
#   `Drop` surface are textually equivalent to drop-before-rebase-7, so the missing witness
#   predates it. That tag's leak list does not name this file, but that list carries its own
#   record of stale attributions, and the constraint gap it would have needed to avoid is
#   demonstrably present in its own source.
#
# --- not a compiler leak, pinned deliberately ---
#
#   index_assign.an -- 8 bytes. The program itself does `p: Ptr I32 = malloc 8` and
#   never frees it. `Ptr t` is Copy with a no-op Drop impl, so this is correct behavior.
#
