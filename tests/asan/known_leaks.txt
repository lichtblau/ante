#
# --- the abort contract (owned by the abort design, not a later pick) ---
#
#   A handler that completes without resuming discards the suspended continuation.
#   Nothing on it is torn down: no drops run, and nothing double-frees.
#
#   effects/drop_matrix/abort_pinned_leak.an -- 68 bytes, the two continuation Strings,
#     in 4 allocations. The coroutine buffer itself is freed (mco_coro_free runs).
#
#   effects/abort_within_coroutine.an -- 58656 bytes: a WHOLE coroutine stack from
#     mco_create. The cross-stack case: the abort longjmps from the inner generator's
#     coroutine to a setjmp on the OUTER generator's coroutine, so the inner one is never
#     mco_destroy'd. Isolated at M3 -- the same nesting without the abort leaks nothing,
#     and the same nesting through Std.Stream.foldr is clean, so this is the discarded
#     continuation, not the stream shape. Freeing it needs the abort path to destroy the
#     coroutines it unwinds past. (M5 cleared this file's other 32 bytes of payload.)
#
# --- Drop impl not in scope at the use site ---
#
#   A container's `Drop` impl lives in its own module: `import Std.Vec` does NOT bring it
#   in, only `import Std.Vec.drop_vec` does. Drop synthesis never sees it, derives a
#   structural drop over all-Copy fields, prunes to None, and the buffer leaks. The open
#   question is whether the fix is the import or module-level impl visibility, so the
#   test files are left alone pending that decision.
#
#   stdlib-tests/env.an (24), stdlib-tests/io.an (108), stdlib-tests/vec.an (464),
#   implicit_import.an (8).
#
# --- Drop impl IS imported and it still leaks ---
#
#   stdlib-tests/map.an (84, drop_hashmap), stdlib-tests/rc.an (32, drop_rc),
#   stdlib-tests/seq.an (148, drop_seq). Plain `main` locals; rc.an also does manual

#
